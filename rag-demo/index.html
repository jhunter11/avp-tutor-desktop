  1. Prepare passages with source IDs and visibility rules.
  2. Embed an AVP question and compare all 384 components.
  3. Inspect the exact three-vector span in 3D; full search stays in 384 dimensions.
  4. Read the original cited syntax, then return text through the tutor API.
  5. Inspect failures before expanding the corpus.

Why build this now?

Test the small complete path before expanding the corpus: source ingestion, chunk boundaries, retrieval and delivery to the frontend.

Fresh challenge questions found a limitation: related source text can still answer an unsupported question. Review source support and missed paraphrases before claiming that corpus expansion is the only remaining task.

Open decisions

  • Which model and message format give useful, source-supported help?
  • Which course notes, syntax rules and examples should enter the corpus?
  • Can metadata filters serve syntax and algorithm concepts, or do their needs justify separate indexes?
  • Which passages need manual chunks, and which automatic settings improve retrieval?
  • How will we evaluate live answer quality separately from source retrieval?

The old frontend keeps its fixed tutor request and text response. Live generation, broader independent evaluation and team deployment review remain separate work.
